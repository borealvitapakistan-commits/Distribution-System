# Safe GitHub / Vercel release

## Objective
Push the tested work to GitHub and verify its Vercel deployment without including secrets/local data, rewriting remote history, or running deployment-time data imports/migrations.

## Tasks
1. Verify remote history and outgoing content, harden Vercel request/response limits and ignored desktop artifacts, and update the deployment instructions to match the existing Git integration.
2. Push a release branch, open a PR, verify GitHub CI and Vercel preview before merging into main, and verify production status/health with a rollback reference retained.

## Success criteria
Only intended source changes are pushed. Production receives a tested commit after review checks. No credentials, backups, local databases or workbook exports enter Git. No automatic production migrations/imports. Report actual check/deployment outcomes and any external blocker honestly.
